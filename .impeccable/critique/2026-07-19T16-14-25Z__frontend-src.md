## Anti-Patterns Verdict

### LLM assessment

界面像快速拼装的 Element Plus CRUD/聊天原型：默认蓝灰、每页一张大白卡、默认控件和 emoji 字符图标。它没有渐变文字、玻璃拟态或过度动效等严重装饰性反模式，真正的问题是功能状态不可信、移动端失效、错误恢复不足和信息架构偏内部调试工具。

### Deterministic scan

`detect.mjs --json frontend/src` 仅发现 1 条 `side-tab`：`frontend/src/styles/main.css:171` 的 3px 左边框。它用于 Markdown `blockquote` 的引用语义，不是卡片装饰侧条，判定为高概率假阳性。

### Visual evidence

主评估浏览器完成了桌面和 390×844 核验：

- 知识库显示 2 条 ready 文档，但任一 preview 都返回 404。
- 历史和详情直接展示 Elasticsearch `ConnectionError`。
- 390px 覆盖下有效内容宽 375px、页面滚动宽 584px；品牌被逐字挤压，导航超出屏幕。
- 知识库表格宽 1120px，出现页面级双向滚动。

两名隔离子评估代理的 browser list 均为空，因此没有可靠的子代理 overlay；没有声称 overlay 成功。

## Overall Impression

基础页面和状态组件已经足以支持内部验证，但“页面显示的事实”和“系统真实状态”不一致，导致用户无法信任文档、答案和保存结果。最大的机会不是视觉换皮，而是把上传、预览、限定文档问答、证据定位和记录留存做成一个确定性闭环。

## What's Working

1. 文档上传已具备格式校验、进度、处理阶段、失败状态和重析入口。
2. 聊天已有推荐问题、Enter 发送、流式反馈、自动滚动和停止生成。
3. 视觉总体克制，支持 reduced motion；表格链路的 53 个单测当前全部通过。

## Priority Issues

### [P0] 文档列表与真实文档漂移

**Why it matters**：用户看到“已入库”后仍无法预览，核心任务直接阻断。  
**Fix**：使用事务事实源保存文档/版本/任务；增加孤儿数据扫描；ready 必须同时验证文件、IR、preview 和 ES。  
**Suggested command**：`$impeccable harden`

### [P0] 未消毒 HTML/Markdown 可形成存储型 XSS

**Why it matters**：上传文档和模型输出都是不可信输入，可跨问答、预览和历史执行。  
**Fix**：统一安全渲染组件与严格 allowlist；补恶意 HTML 测试。  
**Suggested command**：`$impeccable harden`

### [P0] 聊天错误和保存协议会伪装成功或丢数据

**Why it matters**：多轮 history 未使用，provider 异常可作为答案存储，保存失败仍清空。  
**Fix**：SSE 终态 `done|error|cancelled` 三选一；真正传入历史；保存成功后才清空。  
**Suggested command**：`$impeccable harden`

### [P0] 文档删除/重析缺少事务和补偿

**Why it matters**：可能留下不可管理但仍可检索的敏感 chunk，或在新解析失败后丢失旧版本。  
**Fix**：版本化 staging、成功后原子切换、可验证删除和重试补偿。  
**Suggested command**：`$impeccable harden`

### [P1] 移动端页面结构阻断主任务

**Why it matters**：390px 下导航、输入和表格不可正常操作。  
**Fix**：移动导航、移动列表/抽屉、44px 触控目标和禁止 body 横向滚动。  
**Suggested command**：`$impeccable adapt`

### [P1] 证据链没有形成页面闭环

**Why it matters**：高风险保险结论不能从回答一键回到文档、版本、章节和原文。  
**Fix**：结构化 citation、文档范围和预览 block 深链。  
**Suggested command**：`$impeccable shape`

### [P1] 分页、上传队列和轮询不支持规模化

**Why it matters**：100/200 条后记录静默不可达，多文件共享进度，轮询可能持续或竞态覆盖。  
**Fix**：真实分页、逐文件队列、请求去重和任务终态停止。  
**Suggested command**：`$impeccable harden`

### [P1] 无障碍基线未达标

**Why it matters**：辅助文字对比度 2.39-2.56:1，符号按钮无名称，流式状态无 aria-live。  
**Fix**：AA 对比度、语义标签、键盘主旅程和 44px 目标。  
**Suggested command**：`$impeccable audit`

### [P1] 记录信息架构要求用户记忆内部 ID

**Why it matters**：详情顶层入口不符合工作流，历史/收藏/详情重复且认知负担高。  
**Fix**：合并为“记录”工作区，详情从行内钻取，错误/不完整状态独立呈现。  
**Suggested command**：`$impeccable distill`

## Persona Red Flags

### Alex（高频知识工作者）

- 没有结构化来源快捷定位，必须在回答和知识库之间人工搜索。
- 100/200 条后的数据静默不可达，批量管理结果不可信。
- 详情仍需逐行点击或粘贴 ID，缺少高频快捷路径。

### Sam（无障碍依赖用户）

- 多处浅灰文本对比度只有 2.39-2.56:1。
- 发送/停止按钮只有符号，无可访问名称；路由用 emoji 单独承载含义。
- 390px 页面级横向溢出会造成焦点和阅读顺序混乱。

### Riley（压力测试者）

- ready 列表项打开即 404，状态承诺和真实行为冲突。
- 刷新、重析、删除和并发任务可能产生孤儿数据或丢失旧版本。
- 原始连接异常被长期保存并展示，错误恢复与信息边界失效。

## Minor Observations

- 路由 `meta.title` 未同步到 `document.title`。
- 全局 CSS 中 `.toolbar-row` 和 `.status-text` 重复定义。
- emoji、字符箭头和 Element Plus 图标混用，跨平台基线不稳定。
- Favorites 空态只显示默认空表格，没有任务引导。
- 详情删除确认和其他页面的危险操作规则不一致。

## Questions to Consider

1. “详情”如果只能从记录进入，是否还需要占一个顶层导航位置？
2. 一条可据此行动的保险结论，是否必须带文档版本、章节、页码、原文摘录和一键定位？
3. 移动端是正式发布范围，还是应该明确限制为桌面工具？
4. 静态合同审查原型是否应只保留为 demo，直到模板、规则、风险、审批和审计都有真实契约？
5. 当前最重要的产品指标是功能数量，还是“上传到可核验答案”的成功率与耗时？
