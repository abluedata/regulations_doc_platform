## 1. 产品概述

### 1.1 背景与问题

平台现有"智能审查"四步流程为纯前端演示（本地假数据）。演示证明了交互价值，但无真实审查能力。本次将其升级为**真实、可靠、企业级**的审查闭环。

### 1.2 产品目标

用户在 3 分钟内上传一批劳动合同解除/终止协议书、选择版本化范本并调整规则，系统产出**带规则版本、原文定位证据、可解释理由、校准置信度**的风险清单；用户逐条处置（采纳/修改/驳回），全程审计，最后定稿导出可审计报告。整个过程**结果可复现、证据可核验、质量可量化、操作可追责**。

### 1.3 北极星任务

> 法务人员上传一批解除协议，10 分钟内获得全部高风险条款清单（每条可定位原文、可看规则依据与置信度），完成处置后导出带审计痕迹的报告；同一规则版本重跑结果一致。

### 1.4 用户画像与场景

| 用户 | 场景 | 核心诉求 |
| --- | --- | --- |
| 法务/合规人员（单机） | 批量审查解除协议、核对劳动合规 | 不漏高风险、每条有证据与置信度、处置留痕、可导出审计 |
| 知识库运营/规则维护者 | 维护范本与规则 | 规则版本化、可回归验证、变更不影响历史结果 |
| 平台维护/审计人员 | 评估质量、审计、运维 | 召回/精确率可实测、审计不可篡改、依赖健康可观测 |

### 1.5 成功标准

> 四步闭环全程可走通；高风险召回 ≥90%、精确 ≥80%（分层评测实测）；置信度经校准；同一版本重跑一致；审计日志可导出核验；无未授权访问、无 TLS 关闭校验、无内部堆栈进前端。

## 2. 产品范围

### 2.1 本期范围

| 能力 | 范围 |
| --- | --- |
| 合同类型 | 劳动合同解除/终止协议书 |
| 范本 | 1 个内置版本化范本 |
| 规则 | 10–20 条（通用 + 劳动合规 + 文档一致性） |
| 流程 | 批次上传 → 范本 → 规则 → 审查任务 → 处置 → 定稿导出 → 重审 |
| 处置 | 单条处置（HITL 门）+ 任务级定稿 |
| 问答 | 任务范围追问，带可定位引用，无依据拒答 |
| 报告 | 定稿只读快照（Markdown 先行） |
| 评测 | 分层评测 + 置信度校准 + 回归防护 |
| 企业级底座 | 认证/审计/安全/错误协议/可观测/CI 质量门（横切） |

### 2.2 非目标

- 多合同类型、自定义范本、范本市场、自动 OCR、云端导入、额度计量；
- 团队协作与租户隔离的完整实现（仅预留接口与单机强制 loopback；团队模式需另立 P0）；
- 用演示数据冒充真实结果。

## 4. 功能需求

> 每条需求均须满足：加载/失败可重试/空态/部分失败四态覆盖；错误走统一协议（E-06）。

### FR-01 批次上传（P0）
创建批次，上传 1–50 个 PDF/DOCX，逐文件独立进度与状态，失败可单文件重试；批次可重命名/删除（级联清理）；单文件 ≤50MB。
- 验收：逐文件状态机、重试不阻塞批次、疑似扫描件提示不承诺 OCR、删除可验证（本地文件与关联任务级联清零）。

### FR-02 范本选择（P0）
版本化范本库，卡片展示类型/版本/规则数/匹配度（确定性评分可解释），选中展示规则组摘要。
- 验收：范本只读版本化；匹配度贡献项可解释；未选范本阻断进入下一步。

### FR-03 规则配置（P0）
规则组展示（财务/合规/模型），规则启停/灵敏度/模型选择；默认存会话草稿，保存配置才持久化，创建任务总是固化快照。
- 验收：无启用规则或未选范本阻断；配置预览实时汇总；任务快照固化后改规则不影响已建任务。

### FR-04 智能审查任务（P0）
异步任务：确定性规则优先，未命中且 llm_fallback 规则进 LLM 检查；逐块流式产出；支持取消/重审/失败块重试。
- 验收：状态机 `queued→parsing→running→complete|complete_degraded|failed|cancelled`（终态唯一）；进度"已检查 X/Y 块"；取消保留部分结果；`retry_failed_chunks` 只重跑失败块；任务列表入口可找回历史任务。

### FR-05 风险清单与证据定位（P0）
风险按严重度分组，每条含规则版本/严重度/原文片段/页码或章节锚点/解释/建议/校准置信度；点击定位高亮原文；支持按严重度/状态/文档筛选。
- 验收：100% 风险满足"规则版本+原文定位+解释+建议"非空；置信度档位带历史准确率；PDF quadpoints/DOCX 锚点定位正确；零风险空态明确。

### FR-06 风险处置（HITL 门）（P0）
采纳（可编辑建议/解释）/驳回（必填理由），两步确认（提议→批准/修改/拒绝），全程审计。
- 验收：状态 `not_reviewed→accepted/dismissed` 持久化；处置留审计（含 actor/time/reason/request_id）；未提交不产生写操作；拒绝需带理由。

### FR-07 审查问答助手（P1）
任务范围追问，带风险上下文；回答带可定位引用；检索失败明确拒答。
- 验收：切换风险上下文同步；引用可点击定位；无依据不编造；SSE 唯一终态。

### FR-08 报告导出与任务级定稿（P1）
全部处置后定稿（二次确认弹窗展示待处置数）；报告只读快照含任务元信息/汇总/逐条处置结果/审计摘要。
- 验收：定稿后报告不随后续变化；Markdown 先行；报告绑定版本六元组与评测集 hash。

### FR-09 规则与范本管理（P1）
内置规则 CRUD（单机所有用户即维护者，入口在管理区）；规则更新生成新版本，删除被引用规则拒绝；文档级规则启停关联。
- 验收：版本化、引用保护、按文档启停。

### FR-10 评测工具（P0）
分层评测（per-rule×severity×doc_type 的 TP/FP/FN/F1）+ 置信度校准 + 回归评测门 + 覆盖率/拒答指标。
- 验收：见 §8 可靠性需求 R-01/R-02/R-04/R-07。

## 5. 业务流程与状态机

```text
批次：created → parsing(逐文件) → ready | failed（可重试）
任务：queued → parsing → running → complete | complete_degraded | failed | cancelled
风险：not_reviewed ──采纳(可改建议)──▶ accepted
                └──驳回(必填理由)──▶ dismissed
```

规则：终态唯一；`complete_degraded` = 确定性规则完成但 LLM 检查未执行（降级，UI 明示）；失败块可重试；报告定稿后只读。

## 7. 可靠性工程需求（R 类）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| R-01 分层评测 | 按 rule×severity×doc_type 输出 TP/FP/FN/精确率/召回率/F1 + 逐条 FP/FN 清单 | 评测报告可定位到规则与原文 |
| R-02 置信度校准 | 每个 confidence 档位在评测集上计算实际精确率，前端展示"历史准确率" | 校准表随版本发布；llm_unknown 强制人工确认 |
| R-03 可复现 | 任务/报告绑定版本六元组；LLM 显式 seed + 记录 provider model/usage/finish_reason | 同六元组重跑结果一致（diff 为零） |
| R-04 回归防护 | 规则/prompt/模型变更自动跑回归集；高风险召回/精确率降幅 >2pp 阻断 | 回归集与评测集分离且 hash 锁定 |
| R-05 降级链 | LLM 不可用→仅确定性规则+`complete_degraded` 标注；单文件失败→该文件 failed；检索失败→拒答 | 三档降级均有明确 UI 与状态 |
| R-06 错误处理 | 块级幂等（chunk_id+rule_id 唯一键）；LLM 失败指数退避 ≤2 次 + 死信；失败块可单独重试 | 无静默丢块；重试不重复计费/不重复产出 |
| R-07 覆盖率/拒答 | 覆盖率=执行规则数/启用规则数；拒答率+拒答正确率 | 覆盖率 <100% 置 degraded；拒答金标集实测 |

## 8. 企业级需求（E 类）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| E-01 认证授权 | 单机强制 loopback + 拒绝代理暴露（可选本地 token）；团队模式另立 P0（RBAC+归属+审计） | 非 loopback 启动即拒绝；未授权 401 |
| E-02 TLS | 所有 ES/Embedding/LLM/MinerU 客户端 `verify=True`；受信 CA；fail-closed | 删除全部 `verify=False`/`ssl_show_warn=False`/`disable_warnings`；错误证书被拒 |
| E-03 审计 | 追加式 + 单调序号 + 前条 hash（防篡改）+ actor/action/resource/before-after/request_id；只读导出 | 篡改可检测；导出可核验 |
| E-04 密钥治理 | 密钥不入日志、错误统一脱敏；启动校验密钥；团队模式受管密钥 | 日志扫描 0 密钥 |
| E-05 输出消毒 | 唯一安全渲染组件 + allowlist 消毒（覆盖问答/历史/预览/报告/风险解释） | XSS 用例拦截率 100% |
| E-06 错误协议 | 稳定错误码+用户可读说明+retryable+support_id；禁内部堆栈进前端 | 原始堆栈进 UI 数 = 0 |
| E-07 可观测 | request_id/任务/规则/块贯穿结构化日志；耗时/token/成本/错误率指标；依赖健康只读页 | 每条任务可追踪；指标可查 |
| E-08 数据治理 | 备份/恢复脚本 + schema 迁移版本 + 数据出境说明 + 删除可验证 | 恢复演练通过；出境说明可见 |
| E-09 CI 质量门 | 前端 test/lint/typecheck + 覆盖率门；后端 fake 依赖测试；CI 全量 + 回归门 | 门未过不合并 |
| E-10 容量治理 | 最小持久队列 + 背压 + 死信 + 并发上限 + 超时 + 分页 + 速率限制 | 并发/超时可控；列表全量可达 |

## 10. 风险与依赖

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 种子文档授权不确定 | 无法评测 | 决策门 P0 阻断；自备文档方案并行 |
| TLS 修复回归面广 | 现有链路受影响 | 单独 workstream + 全链路回归 + 受信 CA 配置 |
| 规则误报率高 | 信任受损 | 确定性优先+反误报+校准置信度+灵敏度默认 85 |
| LLM 成本/漂移 | 费用/不可复现 | llm_fallback 开关 + 调用量预估 + 版本六元组 + seed |
| 标注人力不足 | 指标无法实测 | 单人标注+独立复核（团队才要求双人） |
| 企业级底座工作量挤占审查交付 | 延期 | 底座设为横切 P0 先行，审查功能流式跟进 |
