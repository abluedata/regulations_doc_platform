# Feature Specification: 智能审查真实后端联通

**Feature Branch**: `main`

**Created**: 2026-07-26

**Status**: Draft

**Input**: User description: "联通智能审查后端，根据现有前端样式与 Mock 数据设计真实业务契约并支持当前四步审查功能；问答助手沿用原工作台智能问答的交互结构；审查采用基础结构检查与知识规则分析结合的方式，确保风险结论、高亮原文、范本及规范文件规则始终一致且可追溯。"

## Clarifications

### Session 2026-07-26

- Q: MVP 应采用可信单文档纵切、完整审查流程，还是完整 Spec 范围？ → A: 完整 Spec 范围（选项 C）。
- Q: 审查问答应原样复用、扩展原接口，还是保持流式事件兼容并使用独立入口？ → A: 保持原工作台流式事件兼容，使用独立的审查问答入口（选项 A）。
- Q: 审查业务 API 应按领域资源、页面步骤、单一聚合还是扩展现有接口组织？ → A: 采用领域资源型 API，并复用现有文档能力（选项 A）。
- Q: 分析任务应采用异步任务资源、单次流式连接还是同步等待结果？ → A: 采用可查询、可恢复且支持幂等启动的异步任务资源（选项 A）。
- Q: 风险高亮应采用混合证据锚点、内容块定位、版面坐标定位还是服务端高亮内容？ → A: 采用格式区分的版面定位：PDF 使用页码与矩形坐标，DOCX 使用段落序号体系（选项 C）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 完成真实审查任务 (Priority: P1)

审查人员上传一个或多个待审文档，选择可用范本，启用所需规则并设置审查偏好，然后启动真实分析。审查人员可以看到每份文档的处理状态，并在分析完成后进入审查结果，而不是看到预置演示数据。

**Why this priority**: 这是把当前四步演示流程转化为可用业务闭环的基础；没有真实任务、状态与结果，其他能力均无法成立。

**Independent Test**: 使用一份包含已知风险的支持格式合同，依次完成上传、范本选择、规则配置和启动分析，验证任务状态可追踪且最终结果来自本次文档与本次配置。

**Acceptance Scenarios**:

1. **Given** 待审文档已解析完成且存在可用范本和至少一条启用规则，**When** 审查人员启动分析，**Then** 系统创建唯一审查任务，冻结本次输入版本并持续展示真实处理状态。
2. **Given** 一个批次包含多份待审文档，**When** 部分文档分析成功而部分失败，**Then** 系统保留成功结果，逐份说明失败原因，并允许只重试失败文档。
3. **Given** 文档仍在上传或解析，**When** 审查人员尝试进入下一步或开始分析，**Then** 系统明确标识尚未就绪的文档并阻止其进入分析范围。
4. **Given** 审查人员离开页面后重新进入，**When** 审查任务仍在运行或已经完成，**Then** 系统恢复同一任务及其最新状态，不重复创建分析。

### User Story 2 - 查看可核验风险与原文高亮 (Priority: P1)

审查人员查看按严重度组织的风险发现，选择任一风险后，文档阅读区定位并高亮本次分析实际命中的原文，同时展示规则依据、范本或规范来源、风险理由和修改建议。

**Why this priority**: 风险结论只有与不可歧义的原文证据绑定，才可被复核、处理和审计；错误高亮会直接破坏审查可信度。

**Independent Test**: 对包含重复句、跨页条款和多处相似表达的 PDF 与 DOCX 测试文档执行审查，逐一点击风险卡片，验证 PDF 通过页码和矩形坐标定位，DOCX 通过段落或表格单元序号及其内部范围定位，而不是仅按字符串首次匹配。

**Acceptance Scenarios**:

1. **Given** 风险发现包含有效原文证据，**When** 审查人员选择风险卡片，**Then** 阅读区滚动到对应位置并仅高亮该风险绑定的原文范围。
2. **Given** 同一句文字在文档中出现多次，**When** 审查人员选择其中一处对应的风险，**Then** 系统根据证据位置定位到正确实例。
3. **Given** 风险所引用的文档版本与当前预览版本不一致或原文校验失败，**When** 系统尝试展示高亮，**Then** 系统不得静默高亮其他文字，而应提示版本不一致并降级到可验证的段落或页级定位。
4. **Given** 风险依据来自范本或规范文件，**When** 审查人员展开详情，**Then** 系统同时展示待审原文、参考内容、来源名称和来源版本。

---

### User Story 3 - 从范本和规范文件形成受控规则 (Priority: P2)

审查人员或知识维护人员将范本、制度或规范文件加入规则来源。系统提取候选审查规则供人工确认；只有明确发布的规则版本可以用于新的审查任务，历史任务继续使用其原有规则快照。

**Why this priority**: 这使审查能力能够随企业范本和规范变化而更新，同时避免规则在分析过程中无版本漂移。

**Independent Test**: 上传一份包含明确金额阈值和通知期限的规范文件，确认提取的候选规则后发布新版本；验证新任务使用新规则，而发布前已开始或已完成的任务结果保持不变。

**Acceptance Scenarios**:

1. **Given** 新范本或规范文件已成功解析，**When** 系统完成候选规则提取，**Then** 用户可以查看每条候选规则的适用范围、判断条件、风险级别、来源证据和待确认状态。
2. **Given** 候选规则尚未人工确认和发布，**When** 用户创建审查任务，**Then** 未发布候选规则不得自动参与分析。
3. **Given** 已发布规则产生新版本，**When** 用户开始新的审查任务，**Then** 新任务使用明确选定的规则版本，运行中和已完成任务不受影响。
4. **Given** 规则来源文件解析失败或来源证据无法定位，**When** 系统处理候选规则，**Then** 对应候选项不得发布，并向用户说明阻断原因。

---

### User Story 4 - 围绕审查结果连续问答 (Priority: P2)

审查人员在审查控制台中围绕当前任务或当前选中风险提问。助手以与原工作台一致的流式交互、停止和错误反馈方式回答，并将回答限定在本次审查文档、规则和引用证据范围内。

**Why this priority**: 复用用户已经熟悉的问答体验可以降低学习成本；限定上下文则避免通用知识库内容污染具体审查结论。

**Independent Test**: 在同一审查任务中选择一条风险，连续询问判定原因、修改建议和与范本的差异，验证回答保持多轮上下文、引用本次证据，并可被用户停止。

**Acceptance Scenarios**:

1. **Given** 已选择一条风险，**When** 用户询问“为什么被判定为风险”，**Then** 助手基于该风险的待审原文、规则依据和参考来源回答并附带可定位引用。
2. **Given** 用户继续追问修改建议，**When** 助手生成回答，**Then** 回答继承本次会话上下文，无需用户重复风险背景。
3. **Given** 回答正在生成，**When** 用户执行停止操作，**Then** 生成停止，已展示内容保留，并明确标识回答未完成。
4. **Given** 问题超出本次审查可用资料，**When** 助手无法从限定范围获得依据，**Then** 助手明确说明证据不足，不以其他文档或无来源内容补充确定性结论。

---

### User Story 5 - 处理并导出审查结论 (Priority: P3)

审查人员可以对单条风险记录处理意见，对本次审查草稿作通过或驳回决定，并导出与当前可见结果一致的审查报告。

**Why this priority**: 审查发现需要进入人工决策和交付流程，才能形成完整业务结果；该能力依赖前述真实分析与证据链。

**Independent Test**: 对一项完成的审查标记若干风险处理状态，填写处理意见并完成审批，再导出报告，验证页面、审计记录和导出内容一致。

**Acceptance Scenarios**:

1. **Given** 审查任务已完成，**When** 审查人员对风险记录处理意见，**Then** 系统保存处理状态、意见和操作时间，并在重新进入任务后恢复。
2. **Given** 审查草稿满足处理条件，**When** 审查人员通过或驳回草稿，**Then** 系统记录明确的任务决策且不改写原始分析结果。
3. **Given** 用户导出审查报告，**When** 导出完成，**Then** 报告中的文档版本、规则版本、风险、证据、处理状态和总体决定与当前任务一致。

### Edge Cases

- 文件格式不支持、文件为空、超过大小限制或上传中断时，不得创建可分析文档。
- 扫描件无法稳定提取文字或位置时，文档应显示为需要人工处理，不得生成无法核验的精确高亮。
- 文档中存在重复文本、跨段落、跨页、表格单元格或重叠风险范围时，每项风险仍需保持独立且可验证的证据定位。
- 批次中文档类型不同或与所选范本不匹配时，系统应逐份提示适用性问题，不能用单一结果覆盖整个批次。
- 多条启用规则给出相互冲突的结论时，系统应保留各自依据并标记冲突，交由人工判断。
- 规则或来源文件在分析运行期间被更新、停用或删除时，运行中的任务继续使用已冻结快照。
- 分析没有发现风险时，系统应展示“未发现符合当前规则的风险”，同时保留本次范围和版本信息，不宣称文档绝对无风险。
- 用户快速重复启动、刷新或返回页面时，不得为同一操作产生重复任务或重复结果。
- 问答生成失败、被停止或连接中断时，错误信息不得被保存为助手答案，用户可以针对同一上下文重试。
- 原文版本发生变化、证据文本校验失败或预览无法加载时，系统必须阻止错误高亮并提供可恢复路径。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将当前“文档上传、范本选择、规则配置、智能审查”四步流程连接到持久化的真实审查任务和真实分析结果。
- **FR-002**: 系统 MUST 支持在一个审查批次中提交一个或多个已就绪文档，并为每份文档独立记录状态和结果。
- **FR-003**: 系统 MUST 在开始分析前验证所有纳入范围的文档、范本和规则均处于可用状态；不符合条件的项目必须被明确排除或阻断。
- **FR-004**: 系统 MUST 为每次审查生成唯一身份，并保存创建时间、当前状态、进度、失败原因及可重试范围。
- **FR-005**: 系统 MUST 在任务开始时冻结待审文档版本、范本版本、规则版本、用户启用项和审查偏好，形成可复现的分析快照。
- **FR-006**: 系统 MUST 防止相同用户操作因重复点击、刷新或重连而创建重复审查任务。
- **FR-007**: 用户 MUST 能够离开并重新进入审查流程，继续查看同一任务的最新状态和结果。
- **FR-008**: 系统 MUST 将批次中的部分失败与整体失败区分处理，并允许用户仅重试失败文档。
- **FR-009**: 系统 MUST 结合文档基础结构检查和基于已发布规则来源的内容判断开展审查，不能仅依赖无上下文的相似内容检索。
- **FR-010**: 基础结构检查 MUST 至少覆盖必备条款是否存在、条款层级与完整性、关键主体、金额、日期、期限及可量化阈值。
- **FR-011**: 内容判断 MUST 将待审条款与所选范本、规范文件和启用规则进行对照，并明确区分直接违规、偏离标准、信息不足和需要人工复核。
- **FR-012**: 系统 MUST 为每项风险保存严重度、位置说明、标题、风险理由、命中原文、依据来源、参考内容、修改建议和处理状态。
- **FR-013**: 缺少可核验证据的分析输出 MUST 标记为“需要人工复核”，不得作为确定性违规结论展示。
- **FR-014**: 当不同规则对同一内容给出冲突判断时，系统 MUST 并列保留各项结论、来源和冲突标识，不得静默选择其中一项。
- **FR-015**: 系统 MUST 支持将范本和规范文件登记为规则来源，并区分来源类型、适用文档类型和当前可用状态。
- **FR-016**: 系统 MUST 从可用来源中产生候选规则，并为每条候选规则展示名称、分类、描述、适用范围、判断条件、阈值、默认严重度和原始来源证据。
- **FR-017**: 候选规则 MUST 经人工确认后才能发布；未发布、已停用或来源证据失效的规则不得参与新的审查任务。
- **FR-018**: 对规则的任何实质变更 MUST 产生新版本，并保留旧版本供历史审查复现。
- **FR-019**: 用户 MUST 能够在单次审查中启用或停用允许配置的规则、调整可配置阈值和选择审查偏好，而不改写已发布规则版本。
- **FR-020**: 新发布的范本或规则版本 MUST 只应用于发布后新建且明确选择该版本的任务，不得改变运行中或已完成任务。
- **FR-021**: 每项风险 MUST 绑定到不可歧义的文档版本和格式专用原文位置，并保存足以重新验证该位置的文本证据。
- **FR-022**: PDF 与 DOCX MUST 使用相互独立、可明确区分的位置契约；系统不得依赖相同的通用位置字段推断两种格式的高亮。
- **FR-023**: 系统 MUST 在显示高亮前校验当前位置的原文与风险证据一致；校验失败时不得高亮其他文字，必须提示版本或定位异常。
- **FR-024**: 用户选择风险卡片时，阅读区 MUST 定位并高亮对应证据；用户选择已高亮内容时，风险区域 MUST 能识别对应风险。
- **FR-025**: 系统 MUST 为无法提供精确位置的解析结果提供段落级或页级降级定位，并明确标识定位精度。
- **FR-026**: 审查问答助手 MUST 使用独立于通用问答的审查上下文入口，同时保持与原工作台一致的 `meta`、`status`、`token`、`done` 和 `error` 流式事件，以及停止、重试和错误反馈行为。
- **FR-027**: 每次审查问答请求 MUST 明确关联审查任务、可选的当前风险、请求身份和完整会话历史；系统 MUST 实际使用该历史维持多轮上下文，并允许用户清空当前对话而不影响审查结果。
- **FR-028**: 问答范围 MUST 默认限定为当前审查任务；选择风险后，回答 MUST 优先使用该风险、待审原文、关联规则和参考来源。
- **FR-029**: 问答回答中的事实性审查说明 MUST 提供可定位到本次任务资料的引用；证据不足时必须明确说明，不得跨越审查范围生成确定性结论。
- **FR-030**: 问答停止、失败或连接中断产生的错误信息 MUST 与正常助手回答区分，且不得作为完整答案进入后续上下文。
- **FR-031**: 用户 MUST 能够记录单条风险的处理状态和意见，并对审查草稿执行通过或驳回决定。
- **FR-032**: 系统 MUST 将人工处理决定与原始分析结果分开保存，任何人工操作不得覆盖最初风险内容或证据。
- **FR-033**: 系统 MUST 记录影响审查结论的关键事件，包括任务创建、规则快照、分析完成、风险处理、总体决定和导出。
- **FR-034**: 用户 MUST 能够导出审查报告；报告 MUST 包含文档与规则版本、风险及证据、处理状态、总体决定和生成时间。
- **FR-035**: 所有分析结果和问答回答 MUST 显示其辅助审查属性，避免被表述为替代专业法律判断的最终意见。
- **FR-036**: 用户 MUST 能够为审查批次设置名称、声明文档类型并选择是否需要增强文字识别；这些属性必须随批次保存并影响就绪检查或处理说明。
- **FR-037**: 上传队列 MUST 逐文件展示名称、大小、上传或解析状态、可理解的进度及失败原因，并允许用户在分析开始前移除文件。
- **FR-038**: 范本列表 MUST 支持按分类和关键词查找，并展示真实名称、描述、适用类别、规则数量、发布版本和可用状态，不得显示固定演示数量。
- **FR-039**: 系统 MUST 根据已就绪文档提供范本匹配建议，并展示匹配依据和置信说明；最终范本仍由用户明确选择。
- **FR-040**: 用户 MUST 能够在开始分析前设置 0 至 100 的检测灵敏度、选择一个当前可用的分析配置，并选择“标准标记”或“仅标记高风险”；系统必须将最终取值纳入分析快照。
- **FR-041**: 用户 MUST 能够将当前规则选择、阈值和审查偏好保存为可复用配置；后续使用该配置时必须显示其来源版本及任何已失效规则。
- **FR-042**: 审查控制台展示的风险总数、严重度分布、文档信息和处理进度 MUST 从当前任务结果计算，不得使用固定演示数值。
- **FR-043**: 范本选择和审查控制台中的文档名称、页数、解析状态及内容预览 MUST 与当前批次中的真实文档版本一致。
- **FR-044**: 现有通用问答入口及其调用方 MUST 保持向后兼容；新增审查问答能力不得改变未携带审查上下文的原工作台问答范围、请求语义或事件语义。
- **FR-045**: 审查问答的停止操作 MUST 使用该次审查问答返回的请求身份，只终止对应生成任务，不得影响同一审查中的其他问答或通用问答。
- **FR-046**: 审查业务接口 MUST 按审查批次、范本版本、规则版本、分析任务、风险发现、人工决定和导出结果等领域资源组织；每类资源必须具有独立身份、明确生命周期及与相关版本的引用关系。
- **FR-047**: 现有文档上传、处理状态和预览能力 MUST 继续作为待审文档及规则来源文档的事实来源；审查资源只保存对明确文档版本的引用，不得复制出无法同步的第二套文档状态。
- **FR-048**: 四步页面 MUST 通过组合领域资源完成工作流，不得要求后端以页面步骤作为唯一数据模型；界面步骤调整不得破坏已保存审查资源的读取和处理。
- **FR-049**: 分析 MUST 作为持久化异步任务运行；启动操作必须在分析完成前返回任务身份和初始状态，客户端连接中断不得终止后台任务。
- **FR-050**: 分析启动 MUST 接受可重复使用的操作身份；对同一批次、同一分析快照和同一操作身份的重复请求，系统必须返回同一任务，只有用户明确发起重跑时才能创建新任务。
- **FR-051**: 分析任务 MUST 至少具有 `queued`、`running`、`partial`、`completed` 和 `failed` 状态，并明确记录当前进度、逐文档状态、可用结果及失败原因。
- **FR-052**: 客户端 MUST 能够独立查询分析状态和结果；进度通知可以减少等待延迟，但不得成为恢复任务或取得最终结果的唯一方式。
- **FR-053**: PDF 风险的精确位置 MUST 包含文档版本、页码、页面坐标基准及一个或多个矩形区域，并附带该区域对应的引用原文和校验信息；缺少页码或矩形区域时不得标记为 PDF 精确高亮。
- **FR-054**: DOCX 风险的精确位置 MUST 包含文档版本、稳定的段落或表格单元身份、文档内序号、单元内部字符范围、引用原文和校验信息，以区分同段或同单元内的重复文本。

### Scope Boundaries

- MVP MUST 包含本规格中的全部 P1、P2 和 P3 用户故事及其功能要求；优先级仅表示实现与验证顺序，不表示任何故事可以延期到 MVP 之后。
- 本功能包含当前四步审查工作流、真实任务状态、规则来源与版本、风险证据和高亮、审查上下文问答、人工处理与报告导出。
- 本功能不包含多人协同权限、组织级审批流、电子签署、合同自动改写、在线共同编辑或外部法律数据库采购。
- 本功能不包含外部云盘或第三方文件存储集成；界面中的文件导入首期仅使用本机上传和已有知识库文档。
- 任意自然语言自动成为正式规则不在本功能范围内；自动提取结果必须先成为候选规则并经过人工确认。
- “实时更新规则”表示来源处理并发布后可供新任务选择，不表示运行中的任务随来源变化而改变。

### Key Entities

- **审查批次（Review Batch）**: 用户发起的一组待审文档，包含批次名称、文档范围、总体状态、逐文档状态和创建时间。
- **文档版本（Document Version）**: 某份待审文档在一次分析中使用的不可变版本，包含文件身份、解析状态、内容结构和版本标识。
- **范本版本（Template Version）**: 可选择的标准合同或分析范本版本，包含名称、分类、适用范围、来源和发布状态。
- **规范来源版本（Normative Source Version）**: 制度、法规或其他规范文件的特定版本，作为候选规则及审查依据的来源。
- **候选规则（Rule Candidate）**: 从来源提取但尚未生效的规则建议，包含判断条件、阈值、严重度、适用范围和来源证据。
- **规则版本（Rule Version）**: 已人工确认并发布的不可变审查规则；新任务可以选用，历史任务继续引用旧版本。
- **分析快照（Analysis Snapshot）**: 一次任务开始时冻结的文档、范本、规则和审查偏好集合，用于复现结果。
- **分析任务（Analysis Job）**: 对一个分析快照执行的持久化异步工作，具有唯一身份、幂等操作身份、生命周期状态、逐文档进度、结果引用和失败信息。
- **风险发现（Finding）**: 对特定文档内容的审查结论，包含严重度、理由、建议、证据、状态和使用的分析快照。
- **PDF 证据定位（PDF Evidence Anchor）**: PDF 风险或回答引用的位置，包含文档版本、页码、页面坐标基准、一个或多个矩形区域、引用文本和校验信息。
- **DOCX 证据定位（DOCX Evidence Anchor）**: DOCX 风险或回答引用的位置，包含文档版本、稳定段落或表格单元身份、文档内序号、单元内部字符范围、引用文本和校验信息。
- **审查问答会话（Review Conversation）**: 与某次审查任务关联的多轮消息及限定上下文，可进一步关联到当前风险。
- **人工决定（Review Decision）**: 对单条风险或整体审查作出的处理意见、通过或驳回决定，独立于原始分析结果。
- **审计事件（Audit Event）**: 记录影响审查过程和结果的关键动作、时间、对象版本和结果。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对不超过 50 页且解析正常的单份文档，90% 的审查任务在 5 分钟内产生首个完整可查看结果。
- **SC-002**: 100% 以确定性风险展示的发现都包含可回溯的文档版本、命中原文、规则来源和位置证据；缺少任一项时只允许显示为“需要人工复核”。
- **SC-003**: 在包含重复文本、表格和跨页条款的验收样本中，至少 98% 的风险点击能够首次定位到人工标注的正确原文实例，其余情况必须显式降级且不得错误高亮。
- **SC-004**: 对任一已完成审查，使用其保存的输入快照复核时，文档版本、范本版本、规则版本和原始风险结果的匹配率达到 100%。
- **SC-005**: 对解析正常的范本或规范文件，90% 在 5 分钟内形成可供人工审阅的候选规则；未经确认的候选规则参与正式审查的比例为 0%。
- **SC-006**: 在审查问答中，95% 的请求在 3 秒内显示首段可见响应或明确处理状态；停止操作在 2 秒内得到可见反馈。
- **SC-007**: 100% 的事实性风险解释和范本差异回答包含至少一个可定位引用；超出证据范围的问题明确返回证据不足。
- **SC-008**: 在可用性验收中，至少 90% 的目标用户能够在无额外指导的情况下于 5 分钟内完成上传、选范本、配规则和启动分析四步流程。
- **SC-009**: 在不少于 30 份双人标注文档的试点样本上，高风险发现召回率不低于 85%，精确率不低于 80%，且所有误报和漏报均可追溯到使用的规则与证据。
- **SC-010**: 在同一评审者和同一合同集的前后对照中，使用智能审查后的平均人工审查时间降低至少 30%。
- **SC-011**: 页面结果、重新进入后的任务结果和导出报告之间的风险数量、证据、处理状态及总体决定一致率达到 100%。
- **SC-012**: 四步流程中展示的文件信息、范本规则数、匹配建议、配置摘要和风险统计与当前任务持久化数据的一致率达到 100%，不存在固定演示数据冒充真实结果的情况。

## Assumptions

- 当前阶段沿用本机单用户模式，同一用户同时承担审查人员和知识维护人员职责，不新增多人权限模型。
- 待审文档、范本和规范来源首期沿用现有支持范围：PDF、DOCX，单文件不超过 50MB。
- 规范性分析默认采用“基础结构检查 + 已发布知识规则对照 + 语义判断”的组合，而不是在三者中择一。
- 范本或规范文件更新采用异步处理；“实时”指候选规则确认并发布后立即可供新任务使用，运行中任务使用冻结快照。
- 当前界面展示的模板分类可以继续存在，但只有完成来源校验并处于已发布状态的模板才允许启动真实审查。
- 自动提取的候选规则需要人工确认其适用范围、条件、阈值、严重度和来源证据后才能发布。
- 现有知识库文档处理和原工作台问答能力可作为依赖继续使用，但必须满足本规格要求的审查范围、版本和证据约束。
- 用户上传的合同、范本和规范文件均已获得合法处理授权；更细的租户隔离、保留期限和跨组织共享由后续安全功能定义。
- 审查结论用于辅助专业人员复核，不构成自动法律意见；最终责任由人工审查决定承担。
- 质量指标仅针对已发布、已验证的模板和规则覆盖范围，不对未配置的合同类型承诺同等识别能力。
